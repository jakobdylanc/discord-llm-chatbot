## Split llmcord.py once its rebound globals are tamed
status: done
- Captured 2026-08-27. The prior goal's residual said "consider splitting the module". Measured the coupling before acting rather than splitting on file length alone: an AST pass over `llmcord.py` counts `discord_bot` touched by 13 functions, `config` by 10, `learning_store` by 10.
- **Blocked on a real hazard, not on effort.** `config` is *rebound* (`config = await asyncio.to_thread(...)`) on every message, not mutated in place. Any new module doing `from llmcord import config` would capture the startup snapshot and silently serve a stale config forever, with hot-reload appearing to work. That is a silent-wrong-answer bug, so the split must not be done the obvious way. Nothing does a from-import of a mutable global today (`main.py` imports functions only), so there is no live bug.
- **Slice landed toward it.** `_reload_config` is extracted and `_gate` now has **zero** global writes (was `config`, `curr_model`); it reads only. `on_message` owns the ordering that used to be implicit inside the gate, with the note_human_reply-before-reload sequence preserved deliberately so a broken config cannot stop the reward loop from recording human replies.
- **Next op, sized.** Medium: give the rebound globals a holder (a module-level `Runtime` object read through an accessor) so importers cannot snapshot them, then move the pipeline functions out. Small alternative: leave the file at ~900 lines and revisit only when a feature forces it. Do not attempt the split before one of those.
- **Closed 2026-08-27.** Globals tamed first, then the split. `runtime.py` (92) holds the `runtime` singleton and the never-rebound shared objects; `pipeline.py` (489) holds gate/assemble/augment/stream; `llmcord.py` drops **852 -> 417** and keeps only bot wiring. `pipeline` does not import `llmcord`, so there is no cycle. The 1000-line question is answered: no file is over 500.
- **Two things the work surfaced.** The holder had to be named `runtime`, not `state`, because `state` is already the DQN feature vector and ruff flagged the shadow as F823 before it could bite. The split then broke exactly one test, correctly: it patched `llmcord.load_and_validate`, but `_reload_config` resolves that name from `pipeline`'s globals, so the patch had become a no-op. Both are now written down in CLAUDE.md. Dockerfile `COPY` updated for the two new modules and checked programmatically against every local import.
- **Residual.** Still never run against live Discord. `runtime` is a holder, not dependency injection: state is still global, just no longer snapshot-able.
